AI Workstation provides one reusable, defense-in-depth development environment on a remote Linux VPS (`linux/amd64` and `linux/arm64`) powered by Docker and **DeepSeek Harness (DSH)**.

Projects remain ordinary Git repositories on the host under `~/projects/`. Only the currently selected project is mounted into the workstation container at `/workspace`.

The workstation contains the common developer runtime and DeepSeek Harness. DSH installation and DSH state are persisted outside the disposable container filesystem, allowing the container or base image to be replaced without losing Harness state.

## Operational Boundaries

The system enforces four distinct boundaries:

1. **Host management layer** — Docker, projects (`~/projects/`), runtime state (`runtime/`), secrets (`secrets/`, `.env`), and the `ai` CLI (`scripts/ai`).
2. **Workstation container** — Isolated developer runtime (`sandbox` UID `1001`) plus only the selected project mounted at `/workspace`.
3. **GitHub broker** — GitHub App credential flow through a host Unix domain socket (`github.sock`) instead of a Personal Access Token (PAT) or host SSH private key inside the container.
4. **Existing infrastructure & network boundary** — The existing gateway/reverse-proxy stack remains separate, and all development ports bind exclusively to `127.0.0.1` on the host.

### Data Flow

```text
Mac / operator
     │
     │ SSH
     ▼
Host CLI: ai
     │
     ├── project selection
     ├── Git operations
     ├── workstation lifecycle
     ├── Harness lifecycle
     ├── app lifecycle
     ├── cache maintenance
     └── preview/tunnel generation
     │
     ▼
Docker workstation
     │
     ├── selected project at /workspace
     ├── persistent DSH state
     ├── persistent DSH installation
     ├── app runtime state
     ├── Harness runtime state
     └── GitHub broker socket
```

## Design Decisions

### Reusable Container
Common developer tooling belongs inside the base container image (`Dockerfile`). Project source code stays outside on the host under `~/projects/` so adding a new repository does not require rebuilding or tagging a new image.

### Isolated Mount
Only the active repository is exposed to the workstation container at `/workspace`. Inactive repositories under `~/projects/` remain unmounted and unreachable from inside the container.

### Persistent Binary
DeepSeek Harness is installed into `runtime/npm-global` (`~/.npm-global` in container) so DSH can be updated independently via `ai dsh update` without rebuilding container layers.

### Persistent State
DSH configuration and session history (`settings.yaml`, `.credentials.yaml`, `storages/workspace.json`) live in host-persistent `runtime/dsh/` (`~/.dsh` in container), surviving image teardowns and rebuilds.

### No Host Docker Socket
Mounting `/var/run/docker.sock` would give the container root-equivalent control over the host Docker daemon. AI Workstation strictly prohibits mounting the host Docker socket.

### No Host SSH Keys
GitHub access is brokered through short-lived GitHub App installation tokens over a Unix domain socket (`github.sock`) instead of mounting `~/.ssh` or copying long-lived PATs into the workstation.

### Localhost Port Binding
Development servers (`127.0.0.1:3000`, `3001`, `5173`, `8080`, `8000`, `4090:4091`) never bind directly to public interfaces (`0.0.0.0`) on the VPS. Operator access is granted exclusively through SSH port-forwarding or Cloudflare Access tunnels.
