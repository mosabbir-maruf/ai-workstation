Follow the steps below to provision AIWS on your remote Linux VPS (`linux/amd64` or `linux/arm64`) and operate projects with the `aiws` CLI.

## Requirements

### Host System

- Linux host with Docker (`24.0+` recommended).
- Docker Compose v2 support (`docker compose`).
- Git (`2.30+`).
- Python 3 (`3.10+`) with `venv` support (`python3-venv`).
- `sudo`.
- GitHub access to the repositories you will manage.
- Linux host (`amd64` or `arm64`) for the published multi-arch image (`ghcr.io/mosabbir-maruf/aiws:latest`), or a local Docker build otherwise.

The included installer validates Docker, Git, Python 3, Docker daemon access, and Python virtual-environment support automatically.

### Server Posture

- SSH key authentication enabled.
- Password authentication disabled.
- Root SSH login disabled.
- Firewall default deny for incoming traffic.
- Only required public ports open.
- Development ports bound exclusively to `127.0.0.1`.

## Installation

Run the automated host installer:

```bash
./install.sh
```

The installer executes the following steps:

1. Validates host prerequisites (`docker`, `git`, `python3`, `sudo`).
2. Installs Python `venv` support if needed.
3. Creates runtime (`runtime/`), project (`~/projects/`), and secret (`secrets/`) directories with strict permissions (`700`).
4. Creates `.env` from `.env.example` (mode `600`).
5. Creates the Python virtual environment (`.venv/`) and installs `PyJWT[crypto]`.
6. Symlinks `aiws` at `/usr/local/bin/aiws`.
7. Validates the resulting installation.

After installation completes, verify the environment, start the dashboard daemon, and initialize GitHub App authentication:

```bash
aiws doctor
aiws daemon status    # Confirms the HTTP bridge for the Web Console is active
aiws github setup     # Optional: configure GitHub App credentials
aiws github test
```

## Environment Config

`.env.example` contains the workstation runtime variables:

```dotenv
IMAGE=ghcr.io/mosabbir-maruf/aiws:latest
DSH_VERSION=0.1.2-rc.1
ACTIVE_PROJECT=
ACTIVE_PROJECT_PATH=
AIWS_ROOT=
DSH_TRUSTED_HOSTS=
ALLOWED_HOSTS=
GITHUB_APP_ID=
GITHUB_INSTALLATION_ID=
GITHUB_BROKER_SOCKET=
GITHUB_BROKER_GID=
CLOUDFLARED_TOKEN_SET=
CLOUDFLARED_APP_HOSTNAME=
CLOUDFLARED_DSH_HOSTNAME=
CLOUDFLARED_APP_PORT=
```

The `aiws` CLI automatically updates project, GitHub broker, and Cloudflare Tunnel keys in `.env` when configured.

### Permission Rules

- Keep `.env` private (mode `600`) and never commit it to Git.
- Keep `secrets/github-app.pem` private (mode `600`).
- Keep `secrets/cloudflared-token` private (mode `600`).
- Keep `runtime/dsh/` at mode `700` and `runtime/dsh/.credentials.yaml` / `settings.yaml` at mode `600`.
- Prefer SHA-pinned image references (`IMAGE=ghcr.io/mosabbir-maruf/aiws:<commit-sha>`) for deterministic production deployments.
- Pin `DSH_VERSION` when deterministic agent behavior is required.

### Web Console Frontend Environment Variables

When deploying or running the web dashboard (`bklit-ui`), configure `.env.local`:

```dotenv
WORKSTATION_PASSWORD=your-console-password   # Master passphrase for /login security gate
WORKSTATION_API_KEY=your-daemon-api-key      # Server-side Bearer token matching daemon
WORKSTATION_BACKEND_URL=http://127.0.0.1:8000 # Internal/loopback daemon address
NEXT_PUBLIC_SITE_URL=https://workstation.example.com
```

## Daily Workflow

### Operator Session

```bash
aiws doctor
aiws start
aiws run
aiws preview

# Work with DSH / editor / browser

aiws app logs
aiws status

aiws app stop
aiws stop
```

### Core Commands

| Task | Command |
|---|---|
| Start workstation container & Harness | `aiws start` |
| Check container, DSH, Bridge & App status | `aiws status` |
| Start active project dev server (`0.0.0.0` auto-bind) | `aiws run` |
| Print SSH port-forwarding & Cloudflare Anywhere URLs | `aiws preview` |
| Stop active project dev server | `aiws app stop` |
| Stop workstation container, App & Harness | `aiws stop` |

## Command Groups

Run `aiws` or `aiws help` for the built-in command summary.

### Projects

```bash
aiws add <github-url>
aiws remove <project>
aiws list
aiws use <project>
```

- `aiws add` clones a valid GitHub HTTPS repository (`https://github.com/<owner>/<repo>`) into `~/projects/<name>`.
- `aiws use` selects which project is mounted into `/workspace` and recreates the container mount if `aiws` is already running.
- `aiws remove` stops the workstation if removing the active project and deletes `~/projects/<name>`.

### Git

```bash
aiws pull
aiws push "commit message"
```

- `aiws pull` runs `git pull --ff-only` inside the active project directory.
- `aiws push` stages changes (`git add -A`), scans staged filenames for sensitive patterns (`.env`, `.env.*`, `*.pem`, `*.key`, `*.p12`, `*.pfx`, `credentials.json`, `service-account*.json`), aborts and resets staging if any secret file is detected, and otherwise commits and pushes.
