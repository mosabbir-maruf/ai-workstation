## Harness Architecture

DSH installation, DSH state, and Harness runtime metadata are deliberately separated across three host directories:

```text
runtime/npm-global/
    └── DSH installation (@deepseek-ai/dsh)

runtime/dsh/
    └── DSH state/config/history (settings.yaml, .credentials.yaml, storages/)

runtime/harness/
    └── Ephemeral PID/log/runtime metadata (dsh.pid, bridge.pid, harness.log)
```

Inside the `aiws` container (`docker/harness.sh`):

```text
DSH
 └── 127.0.0.1:4090
        ▲
        │
        │ local TCP bridge
        │
Bridge
 └── 0.0.0.0:4091
        │
        ▼
Host: 127.0.0.1:4090
```

This architecture keeps the DSH service bound strictly to container-internal loopback (`127.0.0.1:4090`) while exposing it safely to the host loopback (`127.0.0.1:4090`) via the internal Node TCP bridge on port `4091`.

## Cache Management

### Storage Audit

```bash
aiws cache
```

`aiws cache` is strictly read-only and reports three footprints:
1. `=== Docker ===` — `docker system df`
2. `=== AI runtime ===` — `du -sh ~/aiws/runtime`
3. `=== Project node_modules ===` — `find ~/projects -type d -name node_modules -prune -exec du -sh {} \;`

### Safe Cache Purge

```bash
aiws cache clear
```

Cleans reclaimable **Docker builder cache** (`docker builder prune -af`) and **in-container npm cache** (`npm cache clean --force`) when the workstation is running.

`aiws cache clear` intentionally **never removes**:
- DSH state (`runtime/dsh`)
- DSH installation (`runtime/npm-global`)
- `.env`
- Git repositories (`~/projects/*`)
- Docker images (`ghcr.io/mosabbir-maruf/aiws`)
- Docker containers (`aiws`)
- Docker volumes

### Dependency Reset

```bash
aiws cache clear --deps
```

Removes `node_modules` directories across `~/projects/*` after confirmation (or non-interactively with `--yes`):

```bash
aiws cache clear --deps --yes
```

Recommended dependency reset flow:

```bash
aiws app stop
aiws cache clear --deps
aiws run
```

When `aiws run` starts next, dependencies are reinstalled automatically from the project's lockfile (`npm ci`, `pnpm install --frozen-lockfile`, `yarn install --immutable`, or `bun install --frozen-lockfile`).

## State Recovery

Project source code is protected by GitHub. DSH workflow state (`runtime/dsh`) and `.env` are separate and should be backed up independently.

### Export State

```bash
aiws state export
```

Creates a `0600` permissioned archive at `~/aiws-state-backups/aiws-state-<timestamp>.tar.gz` containing:
- `manifest` (format version, ISO timestamp, and `DSH_VERSION`)
- `.env`
- `dsh/` (`runtime/dsh`)

Store exported state archives off-host in encrypted storage.

### Import State

```bash
aiws state import <archive>
```

Recommended recovery workflow:

```bash
aiws stop
aiws state import /path/to/backup.tar.gz
aiws start
aiws dsh version
```

## Update Layers

AIWS separates updates into three independent layers:

### CLI Update

```bash
aiws update
```

or `./update.sh` — runs `git pull --ff-only` on `~/aiws` and `docker compose pull`.

### Image Upgrade

```bash
aiws upgrade
```

Pulls the latest multi-arch image from GHCR, recreates the `aiws` container, and starts the Harness.

### DSH Update

```bash
aiws state export
aiws dsh update
aiws harness restart
aiws dsh version
```

DSH updates do not require rebuilding the base Docker image because the installation lives in persistent `runtime/npm-global`.

## CI/CD Pipeline

The workstation image is built for `linux/amd64` and `linux/arm64` in GitHub Actions on every push to `main`:

```text
Push to main
     │
     ▼
.github/workflows/image.yml
     │
     ├── checkout
     ├── QEMU (multi-arch)
     ├── Docker Buildx
     ├── GHCR login
     ├── build linux/amd64,linux/arm64
     ├── push :latest
     ├── push :<commit-sha>
     ├── inspect published images
     └── clean old tagged versions
```

Published image references:

```text
ghcr.io/mosabbir-maruf/aiws:latest
ghcr.io/mosabbir-maruf/aiws:<commit-sha>
```

For deterministic production deployments, pin the SHA tag in `.env`:

```dotenv
IMAGE=ghcr.io/mosabbir-maruf/aiws:<commit-sha>
```

## Troubleshooting

### Container Stopped

```bash
aiws start
aiws status
```

### Harness Stopped

```bash
aiws harness status
aiws harness restart
```

### App Startup Error

```bash
aiws app status
aiws app logs

# Clean dependency reinstall if needed:
aiws app stop
aiws cache clear --deps
aiws run
```

### GitHub Auth Error

```bash
aiws github status
aiws github test
```

Never copy a PAT or host SSH private key into the container as a workaround. Verify `ai-github-broker` and `secrets/github-app.pem`.

### Image Inspection

```bash
docker image ls ghcr.io/mosabbir-maruf/aiws
aiws doctor
```
